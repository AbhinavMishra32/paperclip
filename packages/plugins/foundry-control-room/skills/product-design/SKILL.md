# Product design

The starting template provides structure, not a visual identity. Before implementing UI, choose and document a direction grounded in the product audience: typography, color logic, density, shape language, imagery, interaction, and responsive hierarchy.

Customize every visible component. Do not retain starter copy, generic gradients, interchangeable SaaS cards, fake testimonials, fake logos, fake metrics, or placeholder dashboard data. Empty states must say what is actually missing.

Keep the implementation small: reuse primitives, use design tokens, support keyboard navigation and focus states, and test mobile plus desktop. Landing pages explain the real product; authenticated product screens prioritize the actual job. Visual completion requires a browser check and screenshots of real rendered states.
